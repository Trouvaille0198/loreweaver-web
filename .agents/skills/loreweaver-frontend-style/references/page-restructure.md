# Loreweaver 页面重构方法

当用户要求“重构”“重新排布”“现代化”“做一条并行页面路由”时使用。目标是重新建立信息层级、阅读顺序和操作路径，让页面在五秒内呈现清晰主次。

## 1. 先定义页面重心

盘点页面现有元素、数据源、动作和状态，并按用户任务分成三层：

| 层级 | 判断 | 位置 |
| --- | --- | --- |
| 核心内容 | 完成页面主要任务必须持续阅读或操作 | 首屏之后的主内容区或全宽区域 |
| 主流程内容 | 按稳定顺序浏览的正文、媒体、对象目录 | 主栏，顺序由任务优先级决定 |
| 辅助内容 | 紧凑、可持续参照，但不承担主要任务 | 右侧栏、浮层或局部工具区 |

重要内容不能仅因为宽屏有空位而进入右侧栏。右侧栏只承载辅助、紧凑、持续参照的信息；规则、主持工具、正文编辑器等核心内容应进入主栏或全宽区域。

页面顺序应直接反映优先级。导航顺序、DOM 顺序和视觉顺序保持一致，不能让重要入口在导航靠前、内容却位于页面末尾。

## 2. 结构变化的判定（动手前先自检）

页面重构必须改变页面的解剖，而不是卡片边界。动手前确认方案至少命中下表两项，否则只是样式调整，会被打回：

| 解剖要素 | 改变示例 |
| --- | --- |
| 对象概览 | 新增或移动 hero（眉标 + 故事字体标题 + 状态胶囊 + 主操作），替代无概览或挂错层级的横幅 |
| 导航形态 | 页签改为分段控件、层级切换改为锚点导航，而不是同样页签换皮肤 |
| 坐标系统 | 全宽纵向堆叠 ↔ 主栏 + 辅助栏（sticky 工具轨 / 提交轨）工作区 |
| 信息归属 | 对象状态从页面级横幅或其他分区收进对象自己的面板；低频表单从主列降级为工具轨 |
| 重复组件形态 | 页签、选项行、状态 chip、列表行按新层级重做视觉形态（见第 5.1 节清单） |

反例（都不构成重构）：在同一条纵向堆叠里重新分卡、合并或拆分卡片、调整按钮变体、把主要动作挪进挪出卡片、改间距圆角颜色。

**五秒缩略图检验**：动手前先截基线截图（桌面 + 移动），完成后同视口再截一张。两张并排缩小后如果仍会被认成“同一页换了卡片边界”，重构不成立，继续改解剖。卡片级重排几乎必然通不过这项检验——这是最常见的失败方式。

## 3. 先画结构，再写 JSX

用简短结构草图确认信息关系，例如：

```text
对象概览 hero（对象名 + 状态 + 主操作）
分段导航
核心目录与工具（主栏）
主栏：正文、设定、表单主输入  |  辅助栏（sticky）：对象状态、低频工具、唯一主要动作
```

结构必须回答：

- 页面最重要的内容是什么，是否获得最大可用宽度？
- 哪些内容需要连续阅读，是否被侧栏宽度或内部滚动打断？
- 辅助栏移除后，主栏是否自动占满，不留下空列？
- 数据只有零组、一组和多组时，布局是否都自然？对象概览 hero 必须设计零状态文案。
- 手机端是否保持同一任务顺序，而不是简单隐藏区域？

常用解剖模式（可直接套用再按任务裁剪）：

```text
对象概览 hero：accent Surface + 眉标（ui-eyebrow）+ 故事字体标题（clamp 20–28px）+ 状态胶囊 + 次级动作；零状态给出下一步指引
分段导航：全宽分段控件（内衬 3px + 活动项浮起 + shadow-sm），44px 触摸高度，role=tab 必须支持左右方向键
主栏：目录 / 正文 / 表单主输入，获得最大可用宽度
辅助栏（≥1100px 出现，320px 左右，sticky）：对象状态、服务器安装类低频工具、形态与规则、唯一主要动作
```

长表单页把唯一主要动作和关键配置放进 sticky 辅助栏：主栏滚动时提交按钮不消失。sticky 受网格行高约束属于正常行为，验收时用滚动中按钮可见性判断，而不是苛求吸附在某个固定偏移。

## 4. 布局决策

- 核心区域使用独立 `Surface + SectionHeader`，由页面根级 `grid` 的 `gap` 管理节奏。
- 只有需要并行参照时才使用主栏加侧栏。侧栏为空时不渲染，并让主栏切换为单列全宽。
- 同类内容使用自适应网格：一组占满可用宽度，多组在空间允许时并列，空间不足时自动单列。避免固定两列导致单组只占半宽。
- 导航目标使用稳定的语义 class 或 id，并与实际内容一一对应。不同内容使用不同导航名称，不能用一个含糊入口同时代表多个区域。
- sticky 导航必须预留 `scroll-margin`，不能覆盖区域标题；横向导航只能在自身容器滚动，不能撑宽页面。
- 媒体通常位于完成核心阅读或操作之后；只有媒体本身是页面主要任务时才提前。

自适应网格可使用同类结构：

```css
.resource-columns {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(320px, 100%), 1fr));
  gap: var(--space-5);
  min-width: 0;
}
```

## 5. 实现与复用

- 移动现有渲染节点，不在同一页面编排内复制两套相同 JSX。一个区域只保留一条渲染路径。
- 只有稳定模式存在两个以上使用点时才抽成通用组件；页面独有的组合留在 screen，视觉值仍使用共享令牌。
- 复用 `Surface`、`SectionHeader`、`Button`、`Notice`、`EmptyState` 和已有媒体组件。
- 同级间距由父级 `gap` 控制；不通过子项随机 `margin` 修补布局。
- 使用语义令牌、`minmax(0, 1fr)` 和 `min-width: 0`，不增加主题分支或固定颜色。
- 条件区域同时影响 DOM 和网格列定义，避免空 `aside`、空卡片或空半栏。
- 长 Markdown 在桌面端可以拥有明确边界的局部滚动；760px 以下恢复页面级自然滚动，避免嵌套滚动争抢手势。

### 5.1 重复组件必须重做形态

“所有组件都要重构”是硬要求：重构范围内每个重复出现的组件都要按新层级重新设计视觉形态，只搬盒子不改形态同样会被视为没重构。已验证的形态升级方向：

| 旧形态 | 新形态 |
| --- | --- |
| 小 tab 按钮 + 底部下划线 | 全宽分段控件：内衬容器 + 活动项浮起白片 + `shadow-sm` |
| 裸 checkbox/radio 行（`play-skill-row`） | 可选瓦片（`module-option`）：内衬底 + 边框 + `:has(input:checked)` 强调色高亮 + `focus-within` 焦点环 + 禁用灰化 |
| 方角文本 chip | 状态胶囊：`radius-pill` + 语义色 tint（`chip-on` 用 `--lw-success` 派生） |
| 紧凑列表行 | 目录行：15px/650 标题 + 胶囊组 + 等宽字体元信息行 + hover/选中态 |

新形态只能由语义令牌和 `color-mix` 派生，不引入固定色；并加入 `prefers-reduced-motion` 覆盖。

### 5.2 信息归属与跨文件清理

- 对象状态（如“当前房间模组”）归对象自己的面板 hero，不挂在页面级让所有同级分区陪跑。重构时主动撤掉这类横幅并把它收进对象面板。
- 重构是清理 CSS 所有权的机会：同一个类在 `styles.css` 和 `design-system.css` 各有一套定义时（如旧 `.module-tabs`），先确认两文件的导入顺序（`main.tsx` 中 `styles.css` 先、`design-system.css` 后，后者胜出），然后删除旧副本，让新结构只保留一处定义。
- 删掉被新结构取代的旧布局类（如被工作区替代的网格类），不留死规则。

### 5.3 测试断言预检

仓库 `AGENTS.md` 禁止运行测试，CI 只能靠读代码保护。改名、删控件、换结构前，先 grep 测试文件对相关文案、`role`、`label` 的断言（如 `ModuleScreen.test.tsx`、`PlayView.test.tsx`）：被断言的字符串和可访问名必须原样保留（例如 "Module source library"）；权限可见性条件（如玩家座位看不到 pack 表单）同样保持。i18n 新键必须同时进 `en.json` 和 `zh.json`，并用 JSON 解析校验两份文件。

## 6. 并行页面路由

详情页面必须拥有可解析的对象标识，例如 `#/module-detail/<module-name>`。只有路径前缀而没有对象标识时，页面不能可靠加载详情。

并行页面应遵守：

- 路由层准确解析对象标识并请求对应数据。
- 列表请求和详情请求不能相互覆盖或形成竞态。
- 重构页面与基线页面使用明确的 variant 或独立 screen 入口。
- 共享数据、动作和业务组件；页面编排可以不同。
- 回归检查基线页面，确认并行路由的 class、布局和状态没有泄漏。

## 7. 交互完整性

- 折叠内容使用原生 `details/summary` 时，检查键盘焦点、展开状态和长内容边界。
- 图片预览支持按钮打开、关闭按钮、遮罩、`Escape` 和焦点返回。
- popover 或文件菜单支持点击外部和 `Escape` 关闭，关闭后焦点回到触发器。
- 页面导航滚动服从 `prefers-reduced-motion`。
- 手机端触摸目标不小于 44px，横向页签或导航可发现且不产生页面级溢出。
- `role="tab"` 的导航必须支持方向键切换，焦点跟随活动页签。

## 8. 真实页面验收

在 Docker 的 8787 页面使用真实数据验收，不能只看静态代码或空壳路由。

桌面端至少确认：

- 核心区域在 DOM 和视觉上都位于次要区域之前。
- 核心 Surface 使用预期宽度；一组内容占满，多组内容合理并列。
- 侧栏只包含辅助内容，且 sticky 不遮挡页面；滚动中唯一主要动作保持可见。
- 长内容展开后有完整可读边界。
- 用 DOM 几何证明新解剖：主栏/辅助栏宽度、网格列定义、`position: sticky`、DOM 顺序（`compareDocumentPosition`）。

390px 手机端至少确认：

- `document.documentElement.scrollWidth === clientWidth`。
- 页面可自然滚动到底部，核心内容顺序保持不变。
- 自适应网格为单列，按钮和折叠标题达到触摸尺寸。
- 展开长内容后仍无横向溢出，页面滚动与局部滚动边界正确。

可通过浏览器脚本检查关键结构，而不只依赖截图：

```js
() => {
  const primary = document.querySelector(".primary-section")
  const secondary = document.querySelector(".secondary-section")
  const root = document.documentElement
  return {
    primaryBeforeSecondary: Boolean(
      primary && secondary &&
      primary.compareDocumentPosition(secondary) & Node.DOCUMENT_POSITION_FOLLOWING
    ),
    pageOverflow: [root.scrollWidth, root.clientWidth],
    primaryWidth: primary?.getBoundingClientRect().width,
  }
}
```

同时检查控制台错误、Docker HTTP 状态和基线路由。截图用于视觉判断（并做第 2 节的缩略图对比），DOM 几何数据用于证明顺序、宽度与溢出状态。

截图工具注意：CDP 截图偶发超时或返回旧帧；部署后先确认页面实际加载的 CSS hash 与构建产物一致，截图与 DOM 检查矛盾时以 DOM 为准，换新标签页重截。

## 9. 完成判断

页面重构只有在以下条件成立时完成：

- 用户指出的重要内容获得符合其重要性的宽度与顺序。
- 页面结构与基线页面存在清晰、可解释的差异，并通过五秒缩略图检验。
- 重复组件的视觉形态按第 5.1 节重做，不是原样搬进新容器。
- 数据零组、一组、多组和辅助栏缺失时都没有空白布局。
- 共享组件、渲染路径和样式没有无意义复制；旧布局类与跨文件重复定义已清理。
- 测试断言的文案、role 和权限条件未被破坏。
- 桌面与手机真实页面均完成交互和溢出验收。
- 并行路由可以直接打开具体对象，基线路由保持原有编排。
